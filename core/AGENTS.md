# AGENTS.md

> 이 파일은 ai-agent-setup으로 처음 만들어진 공통 규약이다. 이 프로젝트에 맞게 고쳐 쓴다. 다른 프로젝트에도 필요한 개선이면 아래 "ai-agent-setup 원본 고치기"를 따른다.

## 먼저 읽을 것

- **결정 0000** (`docs/decisions/0000-project-definition.md`): 프로젝트 개요, 코드 위치, 설정값(이슈 ID 형식, 실행·테스트 명령 등), 리포 고유 규칙. 이 파일과 결정 0000이 다르면 결정 0000을 따른다.
- **문서화 기준** (`docs/documentation-standard.md`): 코드·주석·문서를 쓸 때 이 기준을 따른다.
- **코드 작성 기준** (`docs/coding-standard.md`): 코드를 쓰거나 고치거나 리뷰할 때 이 기준을 따른다. 린터·포매터 설정과 프로젝트의 기존 컨벤션이 먼저다.
- **용어집** (`docs/glossary.md`, 있으면): 이 프로젝트의 도메인 용어. 여기 없는 용어는 추측하지 않고 사용자에게 묻는다.

## 세션 시작 점검

아래 중 하나라도 해당하면 작업 전에 사용자에게 알린다. 고치는 일은 동의를 받은 뒤에 한다.

- 결정 0000이나 문서화 기준 파일이 없다.
  → `.ai-agent-setup/SETUP.md`의 설치 절차를 제안한다.
- 결정 0000에 비어 있는 항목(`TODO`)이 있다.
  → 비어 있는 절을 한 줄로 알린다. 사용자가 채우자고 하면 `.ai-agent-setup/SETUP.md`의 "4. 결정 0000 채우기"대로 그 항목만 묻는다.
- 지금 쓰는 AI 도구의 스킬 폴더(예: Claude Code는 `.claude/skills/`, Codex는 `.agents/skills/`)에 core 스킬(`commit-message` 등)이 없다.
  → 그 도구의 어댑터 설치를 제안한다. toolkit에 그 도구의 어댑터가 없으면 "아직 정의되지 않았다"고 알리고 `.ai-agent-setup/adapters/README.md`를 안내한다.

위 절차에 필요한 `.ai-agent-setup/` 폴더가 없으면, 아래 "ai-agent-setup 원본 고치기"의 원본 저장소에서 받으라고 안내한다(`git clone <원본 저장소> .ai-agent-setup`). 저장소가 아직 없으면 사용자에게 원본 폴더 위치를 물어 `.ai-agent-setup/`로 복사한다. 이 폴더는 커밋하지 않으므로, 팀원이 clone한 프로젝트에는 없는 것이 정상이다.

## 작업 흐름

1. 작업은 이슈에서 시작한다. 이슈 트래커와 이슈 ID 형식은 결정 0000을 본다.
2. 브랜치 이름은 `feature/<이슈ID>-<짧은-설명>`으로 한다.
3. 프로젝트의 원격 저장소 주소는 문서에 적지 않는다. 필요하면 `git remote -v`로 확인한다.
4. PR을 올리기 전에 결정 0000의 테스트 명령을 실행하고, 이번 변경으로 남길 문서(결정 기록·가이드·용어집·이슈 ID 없는 `TODO`)가 있는지 문서화 기준대로 점검한다. 쓰는 AI 도구에 이 순서를 묶은 커맨드(`finish-issue`)가 있으면 그것을 쓴다.
5. 리뷰 요청은 PR(GitLab은 MR)로 한다.
6. 되돌리기 어렵거나 프로젝트 밖으로 나가는 작업은 먼저 묻는다. push, PR 생성, 이슈 상태 변경·댓글, 파일·브랜치 삭제가 여기에 해당한다.

## 커밋

형식: `<이슈ID> TYPE: 무엇을 왜 바꿨는지 한 줄`. 이슈 ID는 브랜치 이름에서 가져오고, 이슈가 없는 커밋은 ID를 빼고 `TYPE: …`로 쓴다. 한 줄로 부족하면 빈 줄 뒤에 본문을 쓴다.

| TYPE | 쓰는 경우 |
|---|---|
| FEAT | 쓸 수 있는 기능이 생기거나 바뀜 |
| FIX | 잘못된 동작을 고침 |
| REFACTOR | 동작은 그대로 두고 코드 구조만 바꿈 |
| TEST | 테스트만 추가·수정 |
| DOCS | 문서·주석만 수정 |
| BUILD | 의존성, 빌드·배포·CI 설정 변경 |
| CHORE | 위 어디에도 속하지 않는 정리 작업 (폴더 이동, 도구 설정 등) |

한 커밋에 여러 성격이 섞였을 때:

1. 나눌 수 있으면 커밋을 나눈다.
2. 나눌 수 없으면 주된 목적의 TYPE을 쓴다. 기능 추가나 버그 수정에 딸린 테스트·문서는 FEAT·FIX에 포함한다.
3. 그래도 애매하면 FEAT·FIX → REFACTOR → TEST·BUILD → DOCS → CHORE 순서로 앞의 것을 고른다.

도메인에 따라 달라지는 판단(예: "제약 조건을 바꾸면 FEAT")은 결정 0000의 리포 고유 규칙을 따른다.

## 문서와 결정 기록

- 문서는 **가이드**(지금 어떻게 동작하나), **how-to**(무엇을 하나), **결정 기록**(왜 그렇게 만들었나) 세 종류다. 자세한 기준은 문서화 기준을 본다.
- 코드만 봐서는 알 수 없는 결정이 있었으면 결정 기록으로 남길지 사용자에게 묻는다. 결정 기록으로 남길지 코드 주석으로 둘지는 문서화 기준의 "어디에 쓰나"와 "결정 기록 포인터"를 따른다.
- 남기기로 하면 `docs/decisions/TEMPLATE.md`를 복사해 다음 번호로 `NNNN-<짧은-영문-설명>.md`를 만든다. 대화와 코드에서 확인된 내용만 쓰고, 모르는 부분은 사용자에게 묻는다. `docs/decisions/README.md` 목록에도 한 줄 추가한다.
- 결정 기록은 한 번 적용하면 고치지 않는다. 결정을 바꿀 때는 새 기록을 만들고, 이전 기록은 상태만 `대체됨 → [NNNN](…)`으로 바꾼다.
  - **예외: 결정 0000**은 프로젝트 정의라서 내용이 바뀌면 그대로 고친다.

## 스킬

`commit-message`, `write-changelog` 스킬과, 설치했다면 `write-release-note` 스킬이 위 절차를 돕는다. 스킬을 쓸 수 없는 도구에서는 이 문서의 규칙대로 직접 한다.

## ai-agent-setup 원본 고치기

이 파일, `docs/`에 처음 깔린 문서(문서화 기준, 코드 작성 기준, 각 폴더의 README, 용어집, 결정 기록 TEMPLATE·0000), 스킬, 커맨드는 ai-agent-setup에서 복사된 것이다. 고칠 때는 범위를 먼저 정한다.

원본 저장소: `<ai-agent-setup 저장소 주소>` — 자리표시자 그대로면 저장소가 아직 없는 것이니, 원본이 필요할 때 사용자에게 원본 폴더 위치를 묻는다.

- **이 프로젝트에만 필요한 변경**: 프로젝트 파일만 고친다. 같은 스킬이 여러 AI 도구 폴더에 있으면(예: `.claude/skills/`, `.agents/skills/`) 함께 고친다.
- **다른 프로젝트에도 필요한 개선**: 사용자에게 ai-agent-setup 원본도 고칠지 묻는다. 원본 위치는 위의 원본 저장소다.
  - 폴더 경로면 그 폴더의 파일을 직접 고친다. 프로젝트 밖 폴더라서 AI 도구에 따라 접근 허용이 필요할 수 있다.
  - 저장소 주소면 프로젝트 밖에 따로 clone해서 고치고, 그 저장소의 규칙대로 커밋하고 PR을 연다.
  - 프로젝트 파일이 원본의 어느 파일에서 왔는지는 원본의 `SETUP.md` "파일 목록"을 본다. 예: `.claude/skills/write-release-note/` ← `core/skills/write-release-note/`
- 프로젝트 안의 `.ai-agent-setup/`는 받은 그대로 두고 고치지 않는다.
