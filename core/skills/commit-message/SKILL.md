# 커밋 메시지 작성

1. `git status`와 `git diff`(스테이징된 변경 포함)로 무엇이 바뀌었는지 확인한다.
2. 변경을 성격별로 묶는다.
   - TYPE 기준과 여러 성격이 섞였을 때의 규칙은 `AGENTS.md`의 "커밋"을 따른다.
   - 도메인에 따른 판단은 결정 0000의 리포 고유 규칙을 본다.
3. 여러 커밋으로 나누는 게 낫다면 나누는 방법을 제안한다.
4. 커밋마다 `AGENTS.md`의 "커밋" 형식(`<이슈ID> TYPE: 무엇을 왜 바꿨는지 한 줄`)으로 메시지를 제안한다. 이슈 ID는 브랜치 이름에서 가져오고, 찾지 못하면 사용자에게 묻는다. 이슈가 없는 작업이면 ID를 뺀다. 한 줄로 부족하면 본문에 이유를 적는다.
5. 사용자가 동의하면 커밋한다. push는 따로 묻는다.

## 예

```
PROJ-12 FEAT: 결과 파일에 실행 시간 항목 추가
PROJ-12 FIX: 빈 입력에서 결과 파일이 만들어지지 않던 문제 수정
PROJ-12 REFACTOR: 입력 검증을 전처리 모듈로 분리
PROJ-12 TEST: 경계값 입력에 대한 단위 테스트 추가
PROJ-12 DOCS: 실행 방법 how-to 추가
PROJ-12 BUILD: pandas 2.2로 올림
CHORE: 사용하지 않는 예제 폴더 정리        ← 이슈 없는 작업
```
