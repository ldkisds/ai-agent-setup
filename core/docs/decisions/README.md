# 결정 기록 (Decision Records)

> **"왜 그렇게 만들었는가"를 버린 대안이 있는 결정 1개당 1장으로 남기는 곳**입니다.
> 코드를 아무리 읽어도 알 수 없는 결정의 배경·이유·버린 대안을 기록합니다.
> 무엇을 기록 대상으로 삼는지는 [문서화 기준](../documentation-standard.md)을 따릅니다.

## 사용법

1. 이슈 작업 중 설계 선택을 했다면, 머지 전에 자문합니다 — **"이번 이슈에서 코드만 봐서는 알 수 없는 결정이 있었나?"**
2. 있으면 [TEMPLATE.md](TEMPLATE.md)를 복사해 `NNNN-<짧은-영문-설명>.md`로 저장합니다 (NNNN은 다음 번호). 그런 결정이 여럿이면 장을 나눕니다.
3. 관련 가이드 문서에 결정 기록 링크를 한 줄 남깁니다 (가이드에 "왜"를 길게 쓰지 않기 위함).

## 규칙

- **단위는 "버린 대안이 있는 결정 1개"입니다.** 결정에서 따라 나오는 귀결은 부모 장의 결정 절 하위 불릿으로, 배경도 버린 대안도 없는 자족적 사실은 코드에 한 줄로 남깁니다.
- **결정 절에는 "무엇"만 씁니다.** 식·메서드명·정렬 규칙 같은 "지금 어떻게"는 가이드가 담당하고, 결정 기록은 그 가이드를 링크합니다.
- **실측은 결론 한 줄 + 이슈 링크입니다.** 측정 표는 이슈 본문에 둡니다. 단, 측정 자체가 결정의 이유인 경우는 이유 절에 남깁니다.
- **템플릿의 다섯 절 밖에 절을 두지 않습니다.** 아직 확인되지 않은 항목은 작성자 메모나 이슈로 보냅니다 — append-only 문서에는 열린 항목을 추적할 자리가 없습니다.
- **날짜는 결정한 날 하나만 적습니다.** 나중의 갱신은 `- **후속**:` 줄이나 새 기록으로 보냅니다.
- **상태는 `적용됨` · `대체됨 → [NNNN](…)` · `폐기됨` 셋뿐입니다.** 부분 대체·정정·예고된 후속 정리 완료는 상태 줄을 건드리지 않고 바로 아래 `- **후속**: …` 한 줄로 적습니다.
- **아래 목록 표의 제목 열은 파일 h1 제목 그대로**입니다. 표는 색인이므로 별도 요약을 쓰지 않습니다.
- **수정하지 않습니다** (append-only). 결정이 뒤집히면 새 기록을 쓰고, 이전 기록의 상태를 `대체됨 → [NNNN](…)`으로 바꿉니다. **기본 브랜치(결정 0000의 설정값)에 머지된 뒤 허용되는 수정은 상태 줄·후속 줄과 아래 목록 표뿐입니다.**
  - **기본 브랜치에 머지되지 않은 기록은 초안으로 보고 본문 수정을 허용합니다.** 같은 브랜치에서 결정이 바뀌었다면 새 기록을 얹지 말고 본문을 고치세요.
- **짧게 씁니다.** 반 페이지~1장. 완벽한 문서가 아니라 "미래의 나에게 남기는 쪽지"입니다.
- 작성이 귀찮으면 에이전트에게 세션 대화 내용으로 초안을 뽑게 하세요. 검토만 사람이 합니다.
- **예외 — 결정 0000(프로젝트 정의)**: 결정 1개가 아니라 프로젝트의 현재 정의를 담으므로 위의 단위·수정 금지 규칙을 따르지 않습니다. 정의가 바뀌면 그 자리에서 고칩니다. 절은 배경·결정·관련만 두고, 결정 절 아래에 하위 절(개요·코드와 문서·설정값·리포 고유 규칙)을 둡니다 ([0000 파일](0000-project-definition.md)).
