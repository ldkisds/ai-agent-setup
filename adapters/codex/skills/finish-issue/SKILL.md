---
name: finish-issue
description: PR을 올리기 전에 테스트와 문서 점검을 하고, 변경 이력(CHANGELOG.md)과 커밋까지 정리한다. 사용자가 `$finish-issue v0.3.3`처럼 직접 부를 때만 쓴다.
---

PR을 올리기 전 마무리를 아래 순서로 한다. 각 단계의 기준은 `AGENTS.md`, 문서화 기준(`docs/documentation-standard.md`), 같은 스킬 폴더에 있는 스킬에 있고, 이 스킬은 순서와 확인 지점만 정한다.

받은 버전은 사용자가 이 스킬을 부를 때 함께 적은 버전이다. 예: `$finish-issue v0.3.3`이면 `v0.3.3`. 함께 적지 않았으면 받은 버전이 없다.

1. **현재 상태 확인**
   - 현재 브랜치와 아직 커밋하지 않은 변경(`git status`)을 보여 준다.
   - 기본 브랜치(결정 0000)에 있으면 PR을 올릴 수 없으므로 알리고 멈춘다. 결정 0000에 기본 브랜치가 비어 있으면 사용자에게 묻는다.
   - 이번 브랜치의 변경을 모은다: `git diff <기본 브랜치>...HEAD`와 아직 커밋하지 않은 변경.
2. **테스트**
   - 결정 0000의 "테스트 명령"을 실행하고 결과를 보여 준다.
   - 값이 비어 있거나 "이 프로젝트에서는 필요 없음"이면 건너뛰고 그렇다고 알린다.
   - 실패하면 멈추고, 고칠지 그대로 진행할지 묻는다.
3. **문서 점검** — 문서화 기준의 "어디에 쓰나"와 "가이드 frontmatter"
   - 1단계에서 모은 변경을 보고 아래를 확인한다.
     - **결정 기록**: 코드만 봐서는 알 수 없는 결정이 있었는가 → `AGENTS.md`의 "문서와 결정 기록"대로 새 기록
     - **가이드**: 바뀐 파일이 어떤 가이드의 `anchors`에 걸리는가 → 내용이 아직 맞는지 확인하고, 고치거나 `last-verified`를 올린다
     - **용어집**: 새 용어나 뜻이 바뀐 용어가 있는가 → `docs/glossary.md`
     - **TODO**: 이번 변경에 이슈 ID 없는 `TODO`·`FIXME`가 있는가 → `TODO(<이슈ID>)` 형식으로 고친다. 문서 뼈대의 채우기 안내 주석(`<!-- TODO: … -->`, 예: 결정 0000·용어집)은 점검하지 않는다
   - 남길 것을 목록으로 보여 주고, 사용자가 고른 것만 쓴다. 해당하는 것이 없으면 "남길 문서 없음"이라고 알린다.
4. **변경 이력 쓰기** — `write-changelog` 스킬(`../write-changelog/SKILL.md`)
   - 받은 버전이 있으면 그 버전으로 쓰고, 없으면 스킬의 "1. 버전 정하기"대로 묻는다.
   - 범위는 1단계에서 모은 이번 브랜치 변경(`<기본 브랜치>..HEAD`와 아직 커밋하지 않은 변경)으로 넘긴다. 스킬이 범위를 다시 정하거나 묻지 않게 한다.
   - 추가한 항목을 보여 주고 이대로 둘지 확인받는다. 고치라고 하면 고친 뒤 다시 확인받는다.
5. **커밋** — `commit-message` 스킬(`../commit-message/SKILL.md`)
   - 3·4단계에서 고친 문서와 `CHANGELOG.md`도 커밋 대상에 넣는다.
   - 커밋은 스킬의 절차대로 사용자가 동의한 뒤에만 한다.
6. **마무리**
   - 테스트 결과, 3단계에서 남긴 문서, 만든 커밋 목록을 보여 준다.
   - push와 PR 생성은 하지 않는다. 다음에 할 일(push, PR 생성)만 안내한다.
